## Hard constraints (do not violate)

- **No Swift, no AppKit code.** Everything UI-facing is a Tauri webview. Native macOS APIs are called from Rust via Tauri/bindings, never via hand-written Swift/Obj-C source — a build-time Objective-C shim for ScreenCaptureKit is the one exception, and it's still not Swift.
- **Frontend is React + TypeScript** (`frontend/`, Vite-built) — **reversed 2026-08-31, user-directed**; the original "plain HTML/CSS/vanilla JS, no framework" constraint no longer holds. See the "Frontend rewrite" entry below for the full stack and the reasoning.
- **Zero network calls after model download.** The entire pitch is local-first. No default-on telemetry, no remote crash reporting (see `docs/mutter-project-plan.md` Section 11 — error logging is local-only, metadata-only, never transmitted).
- **Zero paid resources for v1.** Ad-hoc code signing, not paid Apple Developer notarization, until/unless the validation gate is met and the app leaves the user's own machine (Section 11/12).
- **No payment, account, or licensing system.** Ever, in v1.

## Architecture at a glance

- `TranscriptionEngine` trait (audio → text) and `TextProcessor` trait (text → text, used by grammar cleanup) are separate — do not conflate them (this was a real bug caught in eng review, plan Section 10).
- `PermissionGate<T>` is one generic state machine (NotRequested/Denied/Granted/Unavailable) shared by mic, Accessibility, and system-audio permissions — not three hand-rolled implementations.
- `EngineError` is a typed enum (`ModelNotLoaded`, `UnsupportedLanguage`, `InferenceFailed`, `Timeout`), not a generic boxed error.
- Native FFI/bridge calls (whisper-rs, the ScreenCaptureKit bridge) are wrapped in `std::panic::catch_unwind` — a panic must never take down the whole app.
- Toggle hotkey, not push-to-talk: press once to start, press again to stop.
- Language is auto-detected from audio, never manually selected in settings.

- **Real operational gotchas hit and fixed, worth knowing before touching the build config again**:
  - `tauri.conf.json`'s `beforeDevCommand`/`beforeBuildCommand` run with CWD = the repo root (the *parent* of `src-tauri/`), not `src-tauri/` itself and not wherever `cargo tauri build` was invoked from — confirmed live by echoing `pwd` from inside the hook.   - A screenshot showing a totally blank white dashboard window turned out **twice** in this session to be a window-focus/Space artifact, not a real render failure — `screencapture -x` can capture the wrong Space/window state after `open`-launching the app fresh. `osascript -l JavaScript` calling `NSRunningApplication.activateWithOptions` reliably brings the real window forward before capturing. Matches this file's own earlier-documented precedent (the "briefly appeared to show a different session" scare) — don't trust a blank screenshot alone as proof of a crash; re-activate and recapture first.

**Two more real bugs found by re-auditing `session.rs` after the whisper fix above (same instinct: untested integration paths deserve suspicion):**

- The 120s auto-continue cap can be hit while a cancel countdown (`Phase::CancelPending`) is pending — capture deliberately keeps buffering in the background during a countdown (module docs). The `at_cap` handling only reacted to this during `Phase::Listening`; during `CancelPending` the notification was silently dropped, `capture/mic.rs`'s audio callback then permanently stops accepting new samples once its own cap flag is set, and a subsequent "resume" (second Escape) would look like it's still recording while actually capturing nothing — a silent data-loss bug, not just a missed UI update. Fixed: the cap is now handled identically during `CancelPending`, auto-continuing the segment without disturbing the countdown UI.
- `TranscriptionEngine` gained a real `ensure_ready()` method (default no-op, overridden by `WhisperEngine` to force its lazy model load) and `session.rs`'s `run()` now calls it — with a visible pill `"loading"` state — before the very first hand-off to the engine in the process lifetime. Previously the plan's own Performance Issue 8 requirement ("first transcription pays load latency, shown via the pill's loading state") was simply never wired: a fresh install's first-ever dictation would sit under a generic "transcribing" label for however long the ~500MB model download took, indistinguishable from a hang. Verified live via the fixture-audio test calling `ensure_ready()` then `transcribe()` in sequence.

**Grammar cleanup (Section 5) — updated 2026-08-30, supersedes the 2026-08-29 "not built" decision below.** Option B (local-LLM cleanup) is now real and built, at the user's explicit direction — not the plan's original per-transcript-triggered design, but an **always-on** pipeline stage toggled in Settings (default off). The eng review's own risk (agent-dictation vocabulary getting paraphrased by an always-on pass) still applies and was named explicitly to the user before building; they chose always-on anyway. `engine::pipeline::GrammarPipeline` always runs Option A first, then Option B on top if the toggle is on, falling back to Option A's output if Option B errors so a broken/unavailable model can never block a transcript.

Engine: `candle` (pure Rust), Qwen2.5-0.5B-Instruct GGUF (bartowski's Q4_K_M, ~380MB) + its base repo's `tokenizer.json` (~7MB), downloaded to the same models dir whisper.rs uses, on first use only. **Not `llama-cpp-2`** — that was the first implementation, and a real, verified-live bug killed it: `llama-cpp-sys-2` and `whisper-rs-sys` each statically link their own vendored copy of GGML, and having both in one binary produces hundreds of linker duplicate-symbol warnings that macOS's `ld` doesn't hard-error on. Proven to actually corrupt behavior, not cosmetic: a GGUF file that loaded perfectly in a standalone llama-cpp-2-only binary failed with spurious "tensor is duplicated" errors once linked alongside whisper-rs-sys — on a *different* tensor for two unrelated GGUF files tried, which only makes sense as loader corruption. Switching to `candle` (no vendored C/GGML dependency) eliminated it entirely — confirmed via a clean relink with zero duplicate-symbol warnings, and both `tests/fixture_audio.rs` (whisper) and the new `tests/llm_cleanup.rs` (real GGUF+tokenizer download, real inference) passing together.

Settings: `AppSettings.grammar_llm_cleanup_enabled` (new field, `#[serde(default)]` so existing `settings.json` files on disk don't suddenly opt in), backed by a live `Arc<AtomicBool>` `GrammarPipeline` checks on every call — flipping the dashboard toggle takes effect on the very next transcript, no restart. New Tauri command `set_grammar_llm_cleanup_enabled`.

Original 2026-08-29 decision, for the record: Option A only, for v1; Option B deliberately not built, pending real signal from Phase 8 dogfooding on whether it's actually needed. No such dogfooding signal exists — this was built ahead of that signal, at the user's explicit request, not because the signal arrived.
